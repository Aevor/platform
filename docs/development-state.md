## Codebase filtering + safe file selection (Task 3c, 2026-08-24)

- NEW endpoint `POST /repositories/:id/filter` (Bearer Aevor JWT): deterministic, read-only SELECTION of which workspace files are suitable for future codebase analysis and AI processing. Explicit per-file decisions (`path/size/extension/language/category/included/reason`) + aggregates; no AI, no contents returned, absolute paths impossible.
- NEW package `internal/filtering`: policy tables in `filter.go`, bounded traversal in `service.go`. Reuses Task 3a/3b machinery — `workspace.Manager` containment, `discovery.DefaultIgnoredDirs()` (shared ignore set), `discovery.LanguageForExtension` (exported rename, single language table). The walk is separate from discovery's because it must emit per-entry decisions rather than aggregates; the security-by-construction pattern is identical.
- POLICY ORDER per candidate: secret (.env*, id_rsa/.pem/.key/.jks/credentials.json/.npmrc/... — includes `.env.example` deliberately) → too_large → binary (archives/images/video/audio/db/compiled/fonts/opaque docs) → generated (lockfiles, .min.js/.min.css, source maps, snapshots) → ignored_extension junk text (.log/.bak/.swp/.svg...) → config by name/prefix (Makefile/Dockerfile/go.mod/Cargo.toml/pyproject.toml/requirements.txt/pom.xml/build.gradle*/CMakeLists.txt/.gitignore/.editorconfig...) → documentation by name/prefix (README*/LICENSE*/CONTRIBUTING*/CHANGELOG*...) → docs/config by extension → source by shared tables (+ .sql/.proto/.graphql/.vue/.svelte/.tf/.hcl/.css/.scss/.less/.html labeled additions) → unsupported. Name rules run before extension rules with a word-boundary rule so requirements.txt stays config while install.sh stays source.
- LIMITS: FILTER_MAX_FILE_SIZE (default 1 MiB → excluded `too_large`; never silently truncated), FILTER_MAX_TOTAL_BYTES (default 32 MiB running budget over selected bytes; overflow candidates excluded `total_size_limit`, later files that still fit remain selectable), FILTER_MAX_FILES (default 5000 included → overflow excluded `file_count_limit`). Detail list capped at 1000 path-sorted decisions (`files_truncated` flag); counts always exact. Config fail-fast on invalid values.
- SECURITY: nothing executed; file CONTENTS never read; symlinks never followed (skipped+pruned); only relative slash paths cross the boundary; hostile path shapes fail closed; ignored dirs pruned but never deleted from disk; ownership FIRST then readiness gate then filter. Error surface additions: 504 `filter_timeout`.
- GITIGNORE: deliberately NOT consulted (build hygiene ≠ analysis suitability); independence tested. PERSISTENCE: none — recomputed on demand; no new tables; no source in PostgreSQL.
- Response: `{repository_id, total_files, included_files, excluded_files, total_selected_bytes, languages, exclusion_summary, files[], files_truncated, ignored_directories, symlinks_skipped, truncated, status:"filtered"}`.
- Tests: filtering package (validator/classify matrices incl. traversal + precedence + case-insensitivity; service tests for all selection/limits/symlink/gitignore/determinism cases) + repositories handler matrix (unauth/malformed/foreign≡unknown 404/workspace_not_ready/happy-path exact counts+reasons+languages/zero leakage/node_modules untouched/deterministic bodies).

## Codebase discovery over prepared workspaces (Task 3b, 2026-08-23)

- NEW endpoint `POST /repositories/:id/discover` (Bearer Aevor JWT): READ-ONLY inspection of an already-cloned workspace for one of the authenticated user's selected repositories. Metadata only — no AI, no embeddings, no code analysis, no source content ever returned.
- NEW package `internal/discovery`: pure-Go metadata walker over the server-controlled workspace root. Counts regular files and directories; detects programming languages by file EXTENSION (programming languages only — md/json/yaml/toml cannot drown out code signals); identifies important project/configuration markers (README/LICENSE variants, Makefile, Dockerfile/docker-compose, package.json, go.mod, Cargo.toml, pom.xml, build.gradle, requirements.txt/pyproject.toml/setup.py, composer.json, Gemfile, tsconfig.json, `.github/workflows/*.yml|yaml`) as workspace-RELATIVE paths, capped at 50 entries.
- SECURITY by construction: repository content treated strictly as untrusted data. Nothing executed (no shell/hooks/build tools/CI); file CONTENTS never read into memory (all decisions use names/extensions/Lstat metadata); symlinks NEVER followed (`WalkDir` Lstat semantics — linked files and linked dirs are counted skipped and pruned, so symlink escape can neither leak server files nor leave the workspace); only aggregate metadata + relative paths cross the API boundary.
- IGNORE RULES: directory basenames pruned from the walk (`.git`, `node_modules`, `vendor`, `target`, `dist`, `build`, `out`, `.next`, `coverage`, `__pycache__`, `venv/.venv`, `.gradle`, `.idea`). Ignored content is NOT deleted — excluded from results only. Configurability lives in `discovery.Options{MaxFiles, MaxFileSize, IgnoredDirs}` with package defaults; deliberately NOT env-wired yet (no demonstrated need; avoid config sprawl).
- LIMITS: ≤20,000 files per run (`Truncated=true` beyond that via `fs.SkipAll`), files >1 MiB excluded from counts and tallied as skipped, traversal bounded by request context (cancelled/deadline → `504 discovery_timeout`).
- PERSISTENCE DECISION: NO new table. Discovery recomputes on demand from the filesystem (the same statelessness as `workspace.Ready`; walking is cheap next to cloning). Source files stay out of PostgreSQL entirely; a persisted manifest is deferred until a real consumer exists.
- Service flow mirrors CloneRepository: ownership FIRST (`FindByUserAndID`, unknown ≡ foreign → uniform 404) → workspace readiness gate (`Ready`; missing/corrupted → NEW sentinel `ErrWorkspaceNotReady` → 409 `workspace_not_ready`, remedy = clone first) → metadata walk via injected `discovery.Service`. No GitHub contact, no token use.
- Response: `{repository_id, files, directories, languages:{}, important_files?:[], truncated, status:"discovered"}` — absolute paths impossible by construction.
- Error surface additions: 409 `workspace_not_ready`; 504 `discovery_timeout`. All other mappings unchanged.
- Tests: `internal/discovery/discovery_test.go` (nested-tree counts/languages/markers incl. binary exclusion; ignored dirs pruned-but-preserved; symlink file+dir escape not followed and counted; large-file skip; file-limit truncation; empty workspace zeros; missing root → unreadable; cancelled context → ErrTimeout; extension→language table); `internal/repositories/discover_test.go` (unauth uniform 401; malformed uuid 400; foreign ≡ unknown opaque 404; missing workspace 409; corrupted dir 409; happy path against a REAL cloned workspace asserting exact counts, language map, marker paths, `status:"discovered"` and ZERO leakage of absolute tmp paths/source markers/symlinked server secrets; node_modules content still on disk afterwards; corrupted-workspace 409).

## Secure repository access + workspace cloning (Task 3a, 2026-08-23)

- NEW endpoint `POST /repositories/:id/clone` (Bearer Aevor JWT): ensures one of the authenticated user's selected repositories exists as a private local Git workspace under a server-controlled root. First deterministic step toward codebase-level evidence (Task 3); no AI, no parsing/indexing yet.
- NEW package `internal/workspace`: `Manager` (workspace root validation at construction, per-workspace dirs keyed by the SelectedRepository UUID, `LockFor` per-workspace mutexes, stateless `Ready` = `.git` exists AND `HEAD` resolves, `Reset` wipes partial/corrupted workspaces, `Discard` removes them on failure) and `GoGitCloner` (go-git v5.16.4, pure Go — NO shell-out, therefore no hook execution, no repo-config execution, no command-injection surface).
- Cloning policy: SHALLOW by default (`depth=1`, `SingleBranch`) as the primary resource guard against huge repositories; 5-minute default clone deadline (`DefaultCloneTimeout`) so the synchronous endpoint can never hang indefinitely.
- Credential handling: the plaintext GitHub token exists ONLY in memory for the duration of the operation and travels exclusively via go-git per-operation HTTP basic auth (`x-access-token` username). The URL persisted into each workspace's `.git/config` stays CLEAN (no embedded credentials) — asserted by tests. Tokens never logged, never returned, never stored.
- Clone-URL trust boundary: the clone URL comes ONLY from the AUTHORITATIVE `GET /repositories/{id}` response (never from client input or our stale stored copy). `MakeCloneURLValidator` enforces https to an explicit host allowlist (`CLONE_ALLOWED_HOSTS`, default `github.com`) and rejects http/ssh/scp syntax, host lookalikes, and URLs embedding userinfo credentials. `file://` transport requires an explicit `CLONE_ALLOW_FILE_URLS=true` opt-in (local development/integration only; production keeps it false).
- Config: `WORKSPACE_ROOT` REQUIRED (fail-fast startup validation — workspaces can never be written to arbitrary locations), optional `CLONE_ALLOWED_HOSTS` (CSV, default `github.com`), optional `CLONE_ALLOW_FILE_URLS` (default false). `.env.example` updated.
- Sync/clone flow (service): ownership FIRST (`FindByUserAndID`, unknown ≡ foreign → 404) → decrypted user token → authoritative `GetRepository` → URL-policy validation → per-workspace lock → idempotent short-circuit when `Ready` → `Reset` → bounded clone → post-clone `Ready` verification → any failure `Discard`s the partial workspace (corruption never survives).
- Error mapping additions: clone timeout → 504 `clone_timeout`; Git-endpoint credential rejection → 401 `github_token_invalid`; all other clone failures → 500 `internal` (underlying causes stay in SERVER logs only — they can contain URLs/transport detail).
- Response DTO: exactly `{repository_id, status:"ready"}` — never paths, never clone URLs, never tokens.
- Tests: `internal/workspace/cloner_test.go` (validator matrix incl. userinfo injection + file-opt-in; unreachable-URL classification); `internal/repositories/clone_test.go` (REAL go-git clone from a locally created file:// repository proving working-tree files land and `.git/config` stays token-free; idempotency = second call performs zero clones; corrupted-workspace repair; failure discards partials; auth-rejected/timeout mappings incl. elapsed-time gate; policy-violation matrix with zero cloner invocations; foreign ≡ unknown 404; missing-token; vanished upstream repository; handler contract incl. uniform unauth 401 + identifier-only success body + opaque foreign 404). Pre-existing fixture constructors migrated to a shared `newTestService` helper.

### Part 8 — JWT authentication middleware (complete, verified 2026-08-15)

- `RequireAuth(manager)` enforces `Authorization: Bearer <Aevor JWT>` (approved transport; no cookie; identity never taken from query/body/custom headers).
- Flow: `bearerToken` (exact `Bearer ` prefix, non-empty) -> `manager.Verify` (HS256 whitelist via `WithValidMethods`, `WithIssuer`, `WithAudience`, `WithExpirationRequired`, `sub` parsed as UUID) -> verified `uuid.UUID` stored in Gin context under the typed `UserIDKey` -> `c.Next()`. Every failure aborts with the uniform `401 {"error":"unauthorized"}` via `abortUnauthorized` — never silently continues.
- New `GetAuthenticatedUserID(c)` helper returns `(uuid.Nil, false)` safely when no verified identity exists; handlers consume identity only from context (`GetMe` updated to use it) — no handler parses JWTs.
- JWT is never logged and never echoed in error bodies.
- Tests: `internal/auth/middleware_test.go` (12 test functions) — valid token succeeds; missing/malformed/tampered/expired/wrong-signature/missing-sub/invalid-sub/wrong-issuer/wrong-audience rejected; HS384/HS512 (same secret), `alg=none`, and explicit algorithm-confusion (valid RS256/ES256 signatures) rejected, with an HS256 control proving the whitelist is the discriminator; verified UUID reaches context + helper retrieves it; unauthenticated requests never reach the handler; JWT absent from logs/error responses; query param + `X-User-Id` header cannot override JWT identity; helper fails safely without middleware.
